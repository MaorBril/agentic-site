gremlord vs claude-code-router

claude-code-router (CCR) is the most popular way to point Claude Code at other models, and for good reason: it is a capable control plane with a big plugin ecosystem. gremlord solves the same core problem for a different person. This page is the honest version of who should pick which.

Pick CCR if

  • You want one control plane for several agents and tools, not just Claude Code.
  • You are comfortable running and administering a long-lived router process.
  • You want its plugin and transformer ecosystem.

Pick gremlord if

  • You want Claude Code exactly as Anthropic ships it, unmodified and auto-updating, with nothing to operate. gremlord is a static Go binary; the first session binds the port, the last one out turns off the lights.
  • You want spend control that cannot be talked past: every token priced as it happens, and daily, weekly, or monthly budgets that refuse the next request instead of warning after the fact.
  • You want a classifier to pick the cheapest model that fits each turn, size-checked against each model's real context window before the request goes out.
  • You want gremlord cost to answer "where did today's $4.31 go" without a dashboard.

The honest catch

CCR is older, bigger, and battle-tested by far more users. gremlord is newer and built for one developer's machine, not a team. If you run a team gateway, LiteLLM or CCR is the right layer today. If you are one developer who wants claude, unmodified, with a budget and a cheap-model escape hatch, gremlord installs in one command and has nothing to administer.

One command to a tracked session.

$ curl -fsSL https://raw.githubusercontent.com/gremlord/gremlord/main/install.sh | sh
